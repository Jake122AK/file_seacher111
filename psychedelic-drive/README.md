# MIDNIGHT MUSHROOM DRIVE — Stage 1

**Psychedelic Pixel Driving Rhythm Game** / スマートフォン縦画面 / 4分26秒1本勝負
楽曲: **Thuong Thi Thoi (Jank AIR Remix)** — 132.82 BPM / 147小節

普通に車で家を出ただけだったのに、4分後には宇宙の果てで
フラダンサーと巨大な猫と踊りながら虹の道路を走っている。
——その体験を、外部依存ゼロの HTML5 + Canvas で実装したものです。

## 遊び方

`dist/psychedelic-drive.html` をスマホのブラウザで開くだけ。
（サーバー不要。`file://` でも動きます）

1. 夕方のリビング。テーブルの上の**キノコをタップ**すると主人公が食べる。
2. 数秒間、本当に何も起こらない。やがて家を出て、車に乗り、エンジンをかける。
3. 道路は**5車線**。ノーツが路面を手前へ流れてきます。
   画面下の**判定ライン**に着弾した瞬間、**そのレーンの位置をタップ**。
   画面を横に5等分した領域がそのままレーンです（同時押し対応）。
4. 車はオート走行です。プレイヤーはタップに専念します。
   叩いたレーンへ車が少し寄るので、自分の演奏で車が動いている感触があります。
5. 失敗してもゲームオーバーにも事故にもなりません。空打ちも減点なし。
   **上手く叩くほど世界がトリップします**（下記）。

キーボード（PC確認用）: `S D F J K` が左から5レーンに対応。

### 開発・プレビュー用

| 操作 | 内容 |
|---|---|
| `?skip=1` | 導入シーンを飛ばして 0:00 からドライブ開始 |
| `?t=105` | 任意の秒数から開始（例: 南国突入直後） |
| `PX.game.seek(255)` | コンソールから任意の時刻へジャンプ |
| `PX.game.trip` | 現在のトリップレベル / グルーヴ率 |

## 中核アイデア：叩くほど世界がトリップする

道路は5車線。ノーツが路面を手前へ流れ、画面下の判定ラインに着弾します。
**判定ラインの位置は、そこでの路面の幅がちょうど画面幅になるよう選んであります。**
だから「路面のどのレーンか」と「画面のどこを押すか」が完全に一致します。
レーンは判定ラインから画面下端へ向かって外側に開き、5色に塗り分けられています。

**成功のたびに `tripCharge` が溜まります。**
これがエフェクト強度・リップル・色相・世界の密度に直接乗るので、
叩き続けている間だけ世界がぐんぐん歪み、手を止めると現実に戻っていきます。
PERFECT 8連ごとにドットの花火と画面の震え、24連ごとに世界の色が一段回ります。

判定結果は**音としても鳴ります** — PERFECT はコンボが伸びるほどペンタトニックを
駆け上がり、MISS では音楽が一瞬しゃがみます（duck）。
上手いほど自分の演奏が曲に足され、外すと曲が欠けます。

### なぜステアリング操作をやめたか

当初は「道路の曲線そのものが譜面」で、ハンドルでラインをなぞる方式でした。
これは**画面全体が歪むエフェクトと根本的に両立しません**。
基準となる路面が波打ち・溶け・回転している最中に、その路面に対する
連続的な位置精度を要求していたので、「車が勝手にずれる」感覚が消えませんでした。

タップ式ではタイミングと**離散的なレーン**しか要求しないので、
歪みは判定を一切邪魔しません。むしろ **歪みが報酬になります**。

> 道路のうねり（`chart.pathAt`）は見た目専用で、判定には一切関与しません。

## グルーヴ率でトリップ内容が分岐する

この作品固有の仕組みです。判定精度から `groove (0..1)` を作り、次の3つを同時に動かします。

| groove | 効果 |
|---|---|
| トリップレベル | 最大 **+1.7 / −1.3** レベルが上下する |
| ワールド重み | タイムラインの `worlds` から **`deep`（深い版）** へブレンドされる |
| 路肩の密度 | フラダンサーなどの出現数が最大 **3.4倍**（実測: 66体 → 361体） |
| エフェクト強度 | `tripCharge` が全エフェクトに最大 +22% 上乗せされる |

つまり **音ゲーの腕前 ＝ どこまで深い世界を見られるか**。
上手いと南国の途中で宇宙が滲み出してきますが、ミスが続くと現実寄りに引き戻されます。
リザルトの `TRIP DEPTH` が到達した最深部です。

## トランジション設計（暗転で切り替えない）

世界は「切り替える」のではなく「重みを移す」構造になっています。

* **パレット** — 全ワールドが同じスロット名を持つので重み平均するだけで色が連続的に溶ける
* **背景レイヤー** — 重みをそのままアルファに。山が薄れながらビル群が浮かび上がる
* **路肩オブジェクト** — 種別（`flora` / `house` / `figure` …）しか持たず、見た目は
  **毎フレーム現在のワールド重みから決まる**。だから *すでに生えている街路樹がその場でヤシの木に変わり、さらに先端が星になって宇宙へ繋がる*

`art.js` の `PX.draw.tree(p, x, base, h, m, …)` の `m` が `0 → 1 → 2` と動くと
**広葉樹 → ヤシ → 星** に連続変形します。建物も `m` で 一軒家 → 高層ビル、
`melt` で 窓 → 星 に変わります。これがモーフィングの実体です。

## 楽曲との同期のしかた

音源（`music/track.mp3`）を**そのまま解析して**ゲームを組み立てています。

### 1. BPM と拍位置

オンセット（打点）を検出し、テンポ候補ごとに「16分格子に乗る打点の割合」を測って決めました。

| BPM 候補 | 16分格子適合率 |
|---|---|
| 66.40 | 0.395 |
| 120.00 | 0.452 |
| 126.00 | 0.482 |
| **132.82** | **0.960** |
| 140.00 | 0.524 |

自己相関の第一ピークは 66.4 BPM でしたが、これは**倍テンポの誤り**でした。
格子適合率で見ると 132.82 BPM が圧倒的です（0.96）。
`offset = 0.0376s` が曲頭から1拍目までのズレです。

### 2. 構成（どこで何が起きるか）

低域（キック）と高域（ハット）のエネルギーを小節ごとに測り、構成を割り出しました。
**物語をこの構成にそのまま合わせています。**

| 小節 | 時刻 | 音楽 | ゲーム |
|---|---|---|---|
| 0–11 | 0:00–0:22 | イントロ、ハット薄い | **NORMAL** 普通の住宅街 |
| 12–18 | 0:22–0:34 | キックが太くなる | **SOMETHING IS WRONG** |
| 19–35 | 0:34–1:05 | ハットが開く | **TRIP START** |
| 36–52 | 1:05–1:36 | 最も明るい | **PARADISE** 南国 |
| 53–68 | 1:36–2:05 | — | **COSMOS** 宇宙 |
| 69–82 | 2:05–2:30 | ハットが一度引く | **MEGACITY → JUNGLE** |
| 83–97 | 2:30–2:57 | ハット最大 | **PSYCHEDELIC ZONE** |
| **98–105** | **2:57–3:11** | **キックが抜ける（ブレイクダウン）** | **トンネル** 世界が暗転して静まる |
| **106–121** | **3:11–3:38** | **ドロップが戻る** | **CLIMAX** 全ワールドが一度に戻る |
| 122–131 | 3:38–3:58 | 継続 | クライマックス後半 |
| 132–147 | 3:58–4:26 | ハットが抜けて減衰 | **RETURN** 白い光 → 夜の住宅街 |

**曲の中に本物のブレイクダウンがあったので、そこをトンネルにしました。**
暗転して静まり、ドロップが戻る瞬間にクライマックスが始まります。

### 3. 譜面

検出した打点を16分に量子化し、**高域比（明るさ）の分位点でレーンを割り当て**ています。
低域寄りの打点は中央、高域寄り（ハット・シンバル）は外側のレーンへ。

* **402 ノーツ / 平均 1.63 打/秒**
* レーン使用: `[82, 66, 54, 104, 96]`（5レーンがほぼ均等）
* 密度は曲に追従: イントロ 0.83/s → ブレイクダウン 0.69/s → クライマックス 2.2/s → 帰還 0.30/s

### 4. 映像の同期（音声解析をランタイムで走らせない）

音源の低域/中域/高域エンベロープを **43fps の Uint8** に落として base64 で埋め込んであります
（3帯域で約 45KB）。`Conductor` がこれを読み、遅い移動平均との差分を取って
「キックが鳴った瞬間」を作ります。

だから**道路の脈動・街灯の明滅・建物の呼吸・空の色・車のサスペンション**が
実際に鳴っている音そのものと同期します。AnalyserNode も FFT も要りません。

### 5. 別の曲に差し替えるには

`data/track_song.js` を作り直すだけです。エンジン側の変更は不要です。

```js
window.PX.TRACKS.song = {
  bpm: 132.82, beatsPerBar: 4,
  offset: 0.0376,                       // 曲頭から1拍目まで（秒）
  audioUrl: (window.PX_AUDIO_DATA || 'music/track.mp3'),
  env: { fps: 43.066, low: '<base64>', mid: '...', high: '...' },  // 省略可
  chart: [ { beat: 0, lane: 2, kind: 'tap' }, ... ],               // lane: 0..4
  sections: [ { name:'INTRO', bar:0, energy:.25, amp:.25 }, ... ],
  patterns: null                        // env があれば不要
};
```

`env` を省略した場合は `patterns` の16分ドラムグリッドから映像用エンベロープを
逆算します（仮トラック `track_default.js` がその方式です）。

判定幅は拍単位で PERFECT `±0.10` / GROOVY `±0.19` / GOOD `±0.30`
（132.82 BPM なら ±45ms / 86ms / 136ms）。

## Stage 2 以降の作り方

`data/stage1.js` を複製して `keys[]` を書き換えるだけです。エンジン側の変更は不要です。

```js
{ t: 300,                                  // 秒
  level: 7.0,                              // トリップレベル 0..10
  worlds: { tropical: .55, space: .45 },   // ワールド重み（正規化される）
  deep:   { tropical: .35, space: .65 },   // グルーヴが高い時に寄る“深い版”
  warp:  { rainbow:.55, glow:.9, wave:.4, sky:.12, spiral:0, loop:0, keys:0, liquid:.25 },
  fx:    { sat:.55, rgb:.3, wave:.32, trails:.34, kaleido:.1, melt:0, posterize:0 },
  v:     { speed: 40, signSet:'deep', starBoost:.6, moonFace:1, cloudFace:1 } }
```

`events[]` は一度きりのトリガです
（`cat` / `hueBlip` / `whoosh` / `tunnelIn` / `tunnelOut` / `thirdPerson` /
`mirrorWorld` / `fireworks` / `whiteout` / `musicOut`）。

> **`fx` の値は 0..1 の「許容範囲のうちどれだけ使うか」**です。
> 実際の振れ幅は `src/game.js` の `FX_MAX` がエンジン側の責任として決めています。
> だからデータ側は終盤に思い切って `1.0` と書けますし、
> それでも **走行ラインが読めなくなることはありません**。

## 「エフェクトのインフレ」と可読性の両立

序盤 0〜5%、中盤 30〜50%、終盤 100%、帰還した瞬間に 0 へ——という設計ですが、
全部を全画面に掛けると道路が消えてゲームとして成立しなくなります。
そこで **走行ライン保護マスク** を入れてあります。

`pixel.js` のポストパスは行ごとに `mask[y]` を持ち、地平線より下では
万華鏡・トンネル・回転・ズーム・メルトの効きを最大 90% 落とします。
結果として **サイケデリアは空で暴れ、道路は常に読める**状態になります
（副次的に、重い極座標演算が画面の約半分でスキップされ高速化にも効いています）。

## パフォーマンス

内部解像度 192px 幅の低解像度バッファに描画し、整数倍でニアレストネイバー拡大しています
（＝本物のドット絵。3Dモデルは一切使っていません）。

* 幾何 / 色 / 残像の3パスを **1パスに融合**
* 極座標演算（万華鏡・トンネル）は空の領域のみ
* スプライトの揺れは行単位ではなく最大6バンド
* 毎フレーム `getImageData` する面は `willReadFrequently: true` で CPU 側に置く
  （これが無いとフレーム毎に GPU→CPU 同期が起きて実機で強烈に詰まる）
* 極座標変形は 3px おきに計算して線形補間（見た目は同じで transcendental が 1/3）
* 道路の行ごとの色は 3 行ごとにだけ作り直す（確保と文字列生成が 1/3）
* 路肩オブジェクトは近い順に最大 150 個で打ち切り
* **自動品質調整** — 実処理時間に応じて内部解像度を 192→176→160→144→128 と上下させ、
  段が下がるほど高価な効果（万華鏡・トンネル・メルト）から順に切る

**自動品質は内部解像度を主レバーにしています。** 実測すると、エフェクトを削るより
解像度を1段落とす方がはるかに効くためです（クライマックスで 192px:29fps → 160px:45fps）。
フレームごとの実処理時間を測り、14ms を超えたら 192→176→160→144 と1段ずつ下げ、
9ms を下回ったら1段ずつ戻します。rAF の間隔は vsync で 16.7ms に張り付いて
「余裕があるか」が判定できないので、**間隔ではなく実処理時間**で測っているのが要点です。
エフェクト側の減衰は 60% までに留めてあり、終盤の絵作りは壊れません。

参考値（Chromium / 390x844 / デスクトップ / 自動品質が落ち着いた後）:
全区間 58〜60fps、実処理時間 9〜11ms（予算 16.7ms に対して余裕あり）。

## カメラと自車

視点は**三人称**です。カメラは自車の横位置に **58% の追従率**で遅れてついていくので、
ハンドルを切ると自車が画面内で左右に振れます。これによって
「今どのラインを走っているか」「次のカーブに対してどれだけズレているか」が
車の位置そのもので読めるようになっています。

自車は `art.js` の `PX.draw.carRear()` がプロシージャルに描いています。
すべての寸法を「画面上の半車幅」基準にしているので、遠近で拡大縮小しても比率が崩れません。
ステアリングでキャビンが傾き、キックでサスペンションが沈み、
テールランプがビートで光り、排気煙が後ろへ流れます。

`closeUp` イベント中だけカメラが車に寄って見上げる画になります。

## オブジェクトの遠近と配置

* **建物は正面 + 側面 + 屋根**で描いています（`PX.draw.building2`）。
  側面は消失点へ向かって後退し、そこにも窓が並ぶので奥行きが出ます。
* **建物は「道路側の内側エッジ」を基準に配置**し、必ず外側へ伸ばします。
  高層化しても巨大化しても、道路にはみ出しません。
* **近距離フェード**を種別ごとに変えています。大きい物（建物・浮島・モノリス）は
  早めに消し、小さい物（人・木・標識）は近くまで残します。
  これが無いと、巨大化した建物が至近距離で画面を塞ぐ「壁」になります。
* **樹木は3種類**（広葉樹・針葉樹・ポプラ）を種で選び、暗部→明部→リムライトの
  順に重ねて立体感を出しています（`PX.draw.tree2`）。
* **キャラクターは配色違いを含めて9種類**（フラダンサー3色・通行人3色・子ども・
  ローブの人物・宇宙人・二足歩行の猫）。個体ごとに種を持つので毎フレーム同じ姿です。

## 実装メモ

* 外部リソース・外部通信は一切なし。画像もフォントもすべてコード内で生成しています
  （3x5 ビットマップフォント、文字列アートからのスプライト生成 + 色相バリアント事前生成）
* 音は全て WebAudio による合成（キック／スネア／ハット／ベース／スキャンク／パッド／
  ダブディレイ／エンジン音／SE）。AudioContext はキノコのタップで起動します
* ジャイロ操作は `PX.game.input.enableGyro()` で有効化できます（iOS は許可ダイアログが出ます）
* 音が鳴らない環境でも内部時計にフォールバックしてゲームは最後まで進行します
