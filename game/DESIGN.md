# これからの方針 — 何を作れば「圧倒的に面白い」になるか

書いた日: 2026-08-12
前提: `README.md` の第22稿まで（参道 520m・分岐・水・四ツ辻の眺め・着替え・
三人称の走り・進行方向へのカメラ追従）が入った状態。

---

## 1. いま持っているもの／いちばん惜しいもの

持っているもの:

| | 状態 |
|---|---|
| 太陽 | 緯度 34.9671°、二十四節気、均時差、経度差まで入った**本物**。実際の暦とのずれ 1〜3分 |
| 日照判定 | 鳥居列に対する解析モデルへ光線をマーチ。1サンプル数命令 |
| 世界 | 参道 520m・標高差 58m、区間ごとの性格、分岐、新池と沢、四ツ辻の眺め、お塚 523基 |
| キャラ | リグ39骨・4クリップ・表情6種、三人称、着せ替え、群衆44人（LOD 36分の1） |
| 描画 | 遅延シェーディング・PBR・SSR・ボリューメトリック・カスケード影・TAA・IBL |
| 道具 | `build_*.py` 一式、`blender_autorig.py`、`dress.js`、`export_dressed.py` |

**いちばん惜しいのは、太陽の仕組みが遊びに一度も使われていないこと。**

第1稿の問いは「ダイヤルを回して影が動くのは、それ自体が気持ちいいか？」でした。
答えは Yes だったのに、`shrineplay` ではキョンシーを外し、時刻は自由に回せる
ただのスライダーになりました。**世界で唯一無二の資産が、いまは「きれいな空」に
しか使われていません。** ここを遊びに戻すのが、いちばん費用対効果が高い。

足りないもの:

- **空間が一本の `t`。** 分岐を足しましたが、依然として直線です。「どっちへ
  行く？」が生まれない
- **目的が無い。** 歩く以外にできることが無い
- **時刻が無料。** いつでも巻き戻せる資源は、資源ではない

---

## 2. 背骨の提案 —— 「お山めぐりを、一晩でやる」

実物の稲荷山には環状の巡拝路があります。

    本殿 → 千本鳥居 → 奥社奉拝所 → 新池 → 三ツ辻 → 四ツ辻
      → （右回り）三ノ峰 → 二ノ峰 → 一ノ峰（山頂）→ 御膳谷 → 四ツ辻へ戻る

これは**天然のループ**で、ゲームの地図としてほぼ理想です。分岐・近道・戻り道が
実在の地形として最初から用意されている。

そこへルールを一つだけ足します。

> **時間は進む。戻せない。**

- 時刻は進むだけ（`Q`/`E` の巻き戻しは廃止、`T` の早送りは残す）
- 日没で山の顔が変わる。夜は視界が狭く、狐火だけが道標になる
- どこかで夜を越すと**節気が1つ進む**。太陽の弧が変わり、昨日は日が差していた
  場所に今日は差さない

これで「自由に歩ける」と「選択に意味がある」が両立します。歩く順番・どこで夜を
迎えるか・どの季節でどこへ行くか、が全部プレイヤーの選択になる。

## 3. 段階

### 第1段 — 世界を「一本道」から「地図」へ（最優先。他が全部この上に乗る）

`pathPos(t)` の 1次元を、**区間のグラフ**に一般化します。

```
NODE = { id, pos, name }                     辻・社・分岐点
SEG  = { id, from, to, curve(u), zones, len } 区間（いまの参道が SEG#0）
```

- `groundHeightAt(x,z)` は「最も近い区間」を引く形へ。いまは `t` を1つ解くだけ
- `WORLD.areas` は既に「区域を足せば増える」設計になっている（README に
  「第三の区域を足すなら1行」とある）。**そこがそのまま使える**
- 分岐（`branchOffsetAt`）は、この一般化の特殊解として吸収できる
- `zones.js` は「区間ごとの性格表」なので、辺ごとに持つ形へ移すだけ

最小構成は上のループそのもの。三ノ峰・二ノ峰・一ノ峰は既存の
「石段＋お塚」の組み合わせで作れます。

**危険なところ:** `groundAt` は毎フレーム数十回、加えて遮蔽計算から呼ばれます。
最近区間の探索を素直に書くと O(区間数) が毎回乗るので、z のグリッドか
kd-tree で空間分割が要ります。ここを最初に設計しないと後で刺さります。

**効く理由:** 「どっちへ行く？」が生まれる。いまは「進む／戻る」しかない。

### 第2段 — 時間を資源にする

- 実時間1秒 ＝ ゲーム内 40〜60秒くらい（山を一周して日が傾く長さ）
- 日没・夜明けを演出として立てる（既に空は完璧に計算できている）
- 夜を越すと節気が進む。24節気＝24周ぶんの世界の変化

**効く理由:** **既にある太陽の物理が、そのままゲームのルールになる。**
新しい仕組みを足すのではなく、持っているものに意味を与えるだけ。

### 第3段 — 光と影に意味を与える（キョンシーの再設計）

hiyorimi の「戦闘＝暦」を、環状路の構造に合わせて作り直します。

- 影のものは日向に出られない。鳥居の列は光を縞に切る（実測済み・下の表）
- プレイヤーの武器は「時刻のダイヤル」ではなく、**立ち位置と暦の知識**
- 例:「この社は夏至の朝しか日が差さない」→ そこへ至るには節気を進める＝
  夜を越す＝そのあいだ山は夜になる

実測済みの「光が届く場所」（横オフセット別、`.` は日陰）:

```
             lateral:  -1.0   0.0   1.0
春分  7:00  el 11.3    0.74    .     .
春分 12:00  el 55.0    0.85   0.99  0.90
夏至 17:00  el 24.6     .      .    0.90
秋分  6:00  el  2.1     .     0.28   .
冬至  9:00  el 18.3    0.85   0.83  0.73
冬至 12:00  el 31.6    0.85   0.99   .
```

季節と時刻の組み合わせごとに**答えが違う**。これがそのままパズルになります。

### 第4段 — 自由度の横幅（収集と拠点）

- **お塚（523基）を奉納の対象に。** 名前を刻んだお塚は拠点になる（夜を越せる、
  狐火が灯る）。山中に自分の点が増えていく
- **狐の眷属。** 連れていると夜の視界が広がる。特定の社でしか出会えない
- **御朱印／絵馬。** 「場所 × 節気 × 時刻」の記録。24節気 × 十数か所の
  マトリクスが、そのまま収集の目標になる

### 第5段 — 見せ場

- **一ノ峰の御来光。** 参道の方位 75°（ENE）と日の出方位が一年で交差する
  —— これは既に実装済みの天文がそのまま演出になる。「春分の日の出は参道を
  まっすぐ射抜く」（README 第1稿）
- 四ツ辻の夜景（もうある）
- 千本鳥居を朝いちばんの光が縞に切る（遮蔽モデルがすでに正確）

## 4. 手を付ける順番

1. **区間グラフ**（第1段）—— 空間分割を含めて設計する。ここが土台
2. **時間の一方向化と日没**（第2段）—— ルールが決まると他が全部決まる
3. **夜の視界と狐火** —— 夜が「暗いだけ」だと二周目が苦痛になる
4. **影のルール**（第3段）—— 土台が動いてから調整する

## 5. やらないほうがいいこと

- **世界を「広くする」だけ。** いまの 520m ですら目的が無い。広さは目的の
  あとに足すもの
- **戦闘を先に作る。** 移動と時間の土台が無いと、難易度も配置も調整できない
- **モデルの作り込み。** いまの見た目で既に成立している。袖や髪の毛束は、
  遊びが決まってからで遅くない
- **物量（お塚を1万基に、参道を2kmに）。** 描画は保つが、**歩く理由**が
  増えないので体感は変わらない

---

## 6. ひとことで

**足すのではなく、持っているものに意味を与える。**

太陽は世界一正確に動くのに、まだ何も決めていない。山は一本道なのに、実物は
環になっている。この2つを繋ぐだけで、「歩くと季節が変わり、季節が変わると
行ける場所が変わる」という、他に無いゲームになります。
