# 日和見 — 太陽プロトタイプ

伏見稲荷・千本鳥居を舞台にした「時刻パズル」の第一プロトタイプ。
`hiyorimi.html` をブラウザで開くだけで動く（WebGL2 必須、外部依存ゼロ）。

## このプロトタイプが証明しようとしていること

企画全体の生死を分ける問いは一つだけ:

> **ダイヤルを回して影が動くのは、それ自体が気持ちいいか？**

ここが No ならパズルもナラティブも意味がない。だからこの版はパズルを一問も
入れず、太陽の挙動と手触りだけを作ってある。

## 中核の設計判断 — 太陽を「2本のスライダー」から「暦」に変えた

元の描画エンジンは太陽高度と方位が独立した自由スライダーだった。それでは
パズルにならない。自由度が高すぎて総当たりで解けてしまうからだ。

かわりにプレイヤーが握るダイヤルは2つだけ:

| ダイヤル | 範囲 | 意味 |
|---|---|---|
| **節気** | 二十四節気 24段 | 太陽が描く弧の**形**が変わる |
| **時刻** | 0:00–24:00 連続 | その弧の上のどこにいるか |

高度と方位はこの2つと**緯度 34.9671°N から天文計算で一意に決まる**
(`c2_astro.js` 節)。結果として:

- **到達できない太陽位置が生まれる。** 京都で「真北から低く差す光」は
  一年のどの瞬間にも作れない。これが物理的な壁になり、パズルが成立する。
- **夏至と冬至が極点になる。** 影が最も短い日と最も長い日がゲームの
  「最強の道具」として暦の両端にあり、そこへ至る動機になる。
- **午前と午後で同じ高度が2回来る。** 方位は鏡像、光の色も違う。
  「高度は合っているのに解けない」という良質な引っかかりが自然発生する。

### 実装した天文

二十四節気は黄経15°ごとに正確に並ぶので、節気の番号だけから赤緯が閉じた式で
出る（暦テーブル不要）。均時差と経度差（明石135°Eとの0.77°）も入れてある。

検証値（`node astro_test.js` 相当）:

| | 日の出 | 南中 | 日の入 | 南中高度 |
|---|---|---|---|---|
| 春分 | 06:01 | 12:05 | 18:09 | 55.03° |
| 夏至 | 04:43 | 11:58 | 19:13 | 78.47° |
| 秋分 | 05:46 | 11:50 | 17:54 | 55.03° |
| 冬至 | 07:01 | 16:49 | 16:49 | 31.59° |

実際の京都の暦とのずれは**1〜3分**。南中高度は理論値
(90° − 緯度 ± 23.44°) と小数点以下まで一致する。均時差が効いているので
春分の南中は 12:05、秋分は 11:50 と正しく非対称になる。

### 参道の方位

世界座標 +Z（参道が登る方向）の方位を **75°（ENE）** に設定した。
実際の千本鳥居が東北東に登るのに合わせてあるが、同時にゲーム上の判断でもある:

- 春分・秋分の日の出（方位 89.6°）は**参道をまっすぐ射抜く**
- 夏至は 60.5°、冬至は 118.5°

つまり**一年をかけて日の出が参道の軸を横切る**。これがそのままパズルの
主軸になる。

## 手触りのための実装

- **ダイヤルは目標値。太陽は臨界減衰でそれを追う。** フレームレート非依存
  (`dampWrap`)。時刻は λ=5.5、節気は λ=3.2 と重くしてある（暦が動くのは
  儀式的であってほしい）。真夜中をまたぐときは短い方向に回る。
- **IBL は毎フレーム焼かない。** 太陽の直射（＝影と鏡面）は毎フレーム
  更新するが、環境光キューブは角度が 0.32° 動いたときだけ、しかも
  掃引中は2フレームに1回に間引く。目が追うのは影であって環境光ではない。
- **TAA は太陽が動いている間だけ履歴を捨てる** (`0.88 → 0.54`)。
  動く影に対する TAA ゴーストはパズルゲームでは致命傷になる。
- `T` で早送り（一日 ≈ 28 秒）。`Q`/`E` で時刻、`Z`/`X` で節気。

## グラフィック側で書き直した部分

太陽が一日中どこにでも行けるようになった以上、夕暮れ専用に手で調整された
ライティングは通用しない。物理から出るように書き直した。

- **太陽の色は美術指定ではなく大気の透過率**。天頂での Rayleigh + Mie
  光学的厚さに相対エアマス（Kasten-Young）を掛けて指数を取る。この一本の式
  だけで、南中は暖かい白 (9.9, 9.3, 8.0)、地平線際は深い赤 (1.1, 0.31, 0.01)
  になる。手描きのグラデーションは一切ない。
- **自動露出は実測**。ここは一度作り直した。最初は太陽高度から露出を
  推定していたが、**屋根のある回廊の中では太陽が高いほど目に届く光は
  減る**（笠木が遮る）。開ループ推定は、暗くなった瞬間に絞りを絞る。
  実際に南中の絵が真っ黒になった。
  かわりに描画済みフレームを測る:中央重点の平均輝度を 1×1 のターゲットで
  適応させる（Reinhard 平均。log 平均はこのシーンの真っ黒な領域に
  引きずられて昼夜の差が 1.5 倍しか出なかった）。**読み戻しもストールも
  ない**。明順応は速く (τ≈0.7s)、暗順応は遅く (τ≈1.8s)。
  **完全な正規化はしていない**——`pow(L, -0.75)` にして、夜は夜として
  暁の約 70% の明るさに見えるようにしてある。真夜中と真昼が同じ明るさに
  なるのが自動露出の典型的な失敗なので。
  スライダーは絶対値ではなく**補正**に変えた。ブルームの閾値も露出に
  追従させてある（さもないと南中で画面全体が滲む）。
- **夜**。地平線下でも破綻しないよう、大気光の底と**京都の街明かり**
  （方位300°の地平線、雲の底を舐める）を空シェーダに追加。
- **星**。天球に固定した3オクターブの星野を、天の北極まわりに時角ぶん
  回している。つまり夜のあいだ星は正しく東から昇る。キューブマップに焼くと
  エイリアスするので、空ピクセルに解析的に描いている。
- **石灯籠**は太陽が沈むにつれ点る（点光源と自己発光の両方）。

## 動かす

```
open game/hiyorimi.html          # そのまま開くだけ
game/hiyorimi.html?q=1           # 画質 0/1/2
game/hiyorimi.html?ui=0          # UI なし
```

`window.__DBG` に `CFG` / `R` / `CAM` / `sunENU` / `dayLength` が出ている。

## 次にやること

このプロトタイプで手触りが確認できたら、順に:

1. **影の中判定（CPU側）** — 太陽方向のレイキャスト遮蔽テスト。
   これが無いとパズルが一問も作れない。最優先。
2. **可動オブジェクト** — 灯籠を押す・回す。動的な影を CSM に入れる。
3. **WebAudio** — 環境音・足音・鈴。今いちばん大きな欠落。
4. **平面反射** — 水面パズルには SSR では足りない（画面外を反射できない）。
5. **影ハイライト** — アクセシビリティ。影が見えない環境では詰む。任意ではない。

未着手の既知の限界: 月がない（Act 2）、天候遷移がない（Act 3）、
セーブがない、音がない。
